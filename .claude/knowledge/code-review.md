# Code Review — Accumulated Knowledge

> Living notes for `/code-review` + `code-reviewer`: recurring smells and judgment calls learned with use.
> Authority for the anti-pattern codes stays in `.claude/patterns/code-review-checklist.md`.

## Recurring findings
- **Signal-during-signal race in lifecycle code**: a graceful-shutdown implementation that guards re-entrancy with `if (inFlight) return inFlight` (idempotency) must also ask "what happens if the SECOND trigger carries a payload the first one didn't have (a fatal error to report, a different intended exit code)?" A same-reason second signal is safe to drop; a second signal that upgrades a plain shutdown into a crash is not — the payload (error report, exit code) needs to either merge into the in-flight run or be queued, not silently discarded. Seen in `core/service/lifecycle/graceful-shutdown.ts` (2026-09-17, boilerplate-pombo-v2-update): SIGTERM in flight + `uncaughtException` arriving mid-teardown never reaches `errorReporter` and the process still exits 0. Test coverage had the idempotency case (two plain signals) but not the mixed case — always add the mixed-payload variant when reviewing a re-entrancy guard.

## Judgment calls / calibration
- **Zero-consumer shared DTO is SC-H3 even with a spec.ts**: a shared schema (e.g. `UuidParamSchema` in `shared/dto/common.dto.ts`) that ships with its own unit test but has no call site anywhere in the route layer is still speculative abstraction. A test proves the schema works; it does not prove the abstraction earned its place (BASELINE R27 — "earn it at the second real consumer"). Check consumers with a grep across `modules/*/infrastructure/route/*.routes.ts`, not just "does it have a spec".
- **Static source-scan guard specs (route-mount.spec.ts, tokenContract.spec.ts style)**: when a spec walks source files with a regex instead of importing the app, always check it has a self-defense assertion against silently matching zero files (`expect(files.length).toBeGreaterThan(N)` / `expect(known.colors.size).toBeGreaterThan(0)`). Both specs in this task had it — good pattern to point reviewees at. The remaining known gap in this style of guard: a per-line regex check (`\bfactoryName\b(?!\s*\()`) can be defeated by renaming the import (`import { authMiddleware as auth }`) — not exploited in this diff, but worth a second look if a route file ever aliases a guarded factory import.
